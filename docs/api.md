# Orqentis — REST API Reference

> Base URL: `https://api.fabriccontract.io/v1`
> All endpoints require `Authorization: Bearer {fabricToken}` unless noted.
> All responses are `application/json` and ISO-8601 UTC. Pagination uses cursors.

## Conventions

- Errors use **RFC 7807** `application/problem+json`.
- Every response includes `X-Correlation-Id`. Clients should log it.
- 401 = invalid/expired token. 402 = Community tenant attempting an Enterprise feature.
  403 = valid token but insufficient role. 409 = ETag mismatch on optimistic update.

## Endpoints

(Authoritative table from spec §7. Detailed schemas live in the OpenAPI doc generated by
`Orqentis.Api` at `/swagger/v1/swagger.json`.)

| Method | Path | Description | Tier |
|---|---|---|---|
| GET    | `/contracts` | List contracts | Both |
| POST   | `/contracts` | Create (direct YAML or `ai_generate`) | direct: Both, ai_generate: Enterprise |
| GET    | `/contracts/{id}` | Get contract detail | Both |
| PUT    | `/contracts/{id}` | Update YAML; creates new version | Both |
| DELETE | `/contracts/{id}` | Soft-delete | Both |
| GET    | `/contracts/{id}/versions` | List versions | Both |
| GET    | `/contracts/{id}/versions/{version}` | Specific version | Both |
| POST   | `/contracts/{id}/runs` | Manual enforcement | Both |
| GET    | `/contracts/{id}/runs` | List runs for contract | Both |
| GET    | `/runs/{runId}` | Run detail incl. `result_json` | Both |
| GET    | `/policies` | List policies | Both (read), Enterprise (write paths) |
| POST   | `/policies` | Create policy | Enterprise |
| PUT    | `/policies/{id}` | Update policy | Enterprise |
| DELETE | `/policies/{id}` | Delete policy | Enterprise |
| POST   | `/ai/suggest-contract` | AI generation | Enterprise |
| POST   | `/ai/query` | Natural language query | Enterprise |
| GET    | `/reports/summary` | Tenant health summary | Enterprise |
| GET    | `/reports/audit` | Audit log | Enterprise |
| GET    | `/workspaces` | List workspaces accessible to user | Both |
| GET    | `/workspaces/{id}/tables` | List Delta tables | Both |
| GET    | `/health/live`, `/health/ready` | No auth. Liveness/readiness | n/a |

## `POST /contracts` request body

Two modes — direct YAML or AI generate:

```jsonc
// Mode 1: Direct ODCS YAML
{
  "mode": "direct",
  "name": "Patient Encounters Contract",
  "description": "Governs patient_encounters table",
  "ownerEmail": "owner@example.com",
  "targetTablePath": "abfss://workspace@onelake.../Tables/patient_encounters",
  "targetLakehouseId": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "odcsYaml": "apiVersion: v3.1.0\nkind: DataContract\n..."
}

// Mode 2: AI generate (Enterprise only)
{
  "mode": "ai_generate",
  "name": "Patient Encounters Contract",
  "ownerEmail": "owner@example.com",
  "targetTablePath": "abfss://workspace@onelake.../Tables/patient_encounters",
  "targetLakehouseId": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "aiHints": "Healthcare data, HIPAA context, encounter_id must be unique and non-null"
}
```

## OpenAPI

The API publishes its schema at `GET /swagger/v1/swagger.json`. SDK generation
(TypeScript / Python) is in scope for a future sprint; for now, the frontend models in
`frontend/src/models/` are kept in 1:1 sync with backend DTOs by hand.

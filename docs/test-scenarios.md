# Orqentis FCI Workload — Test Scenarios

Manually validated against production:
- SWA: `https://fabric.orqentis.com`
- API: `https://orqentis-api.azurewebsites.net`
- Workspace: `https://app.fabric.microsoft.com/groups/8e15a176-ac93-4ed2-9540-818214ab1199/list`

Automated coverage:
- `frontend/e2e/workload.spec.ts` runs Chromium coverage for public landing rendering, no-blank-page bootstrap, list/editor rendering, Monaco, routing, theme, correlation headers, bundle secret scan, startup performance, and mocked Fabric proxy lakehouse/table pickers.
- `.github/workflows/ci.yml` runs the Playwright suite on every push/PR after `npm run build`.
- `scripts/Test-CoverageGate.ps1` enforces at least 85% line coverage for `Orqentis.Engine` and `Orqentis.AI` from Cobertura output generated by `dotnet test --collect:"XPlat Code Coverage"`.

## 13. Live authenticated Fabric gates

These scenarios require a real signed-in Fabric session or explicit live-test secrets. They are not safe to run with mocked standalone auth because they prove OBO, Fabric REST, OneLake, and Activator integration.

| # | Gate | Required configuration | Expected |
|---|---|---|---|
| 13.1 | In-Fabric workload iframe smoke | Active browser session in a Fabric tenant with `Org.Orqentis` enabled | Opening a Contract item renders the workload iframe with no blank page and no unhandled console errors |
| 13.2 | Lakehouse/table picker live proxy | Active Fabric workspace containing at least one Lakehouse with one Delta table | Dropdowns populate through backend `/v1/fabric/*` proxy calls; requests include workload bearer token; backend uses OBO to Fabric REST |
| 13.3 | OneLake enforcement regression | `FABRIC_TEST_TENANT_ID`, `FABRIC_TEST_WORKSPACE_ID`, `FABRIC_TEST_CAPACITY_ID`, `FABRIC_TEST_API_BASE_URL`, `FABRIC_TEST_BEARER_TOKEN`, `FABRIC_TEST_PASSED_CONTRACT_ID`, `FABRIC_TEST_DRIFTED_CONTRACT_ID` | Passed contract produces a passing run; drifted contract fails the expected schema rule |
| 13.4 | AI fallback path | Azure OpenAI test config plus forced primary failure or disabled deployment | AI endpoints return fallback template/null-score behavior without throwing to the caller |
| 13.5 | Activator/webhook delivery | Enterprise tenant policy with Activator or Slack/webhook target configured | Failed run dispatches alert within the policy SLA; dispatcher failure is logged with correlation ID |

Recommended execution cadence:
- Run 13.1 and 13.2 after every workload package upload or Fabric manifest change.
- Run 13.3 with the manual **Live Fabric regression** GitHub Actions workflow (`.github/workflows/live-fabric-tests.yml`) because it requires live Fabric credentials.
- Run 13.4 and 13.5 before production releases and after any AI/alerting configuration change.
